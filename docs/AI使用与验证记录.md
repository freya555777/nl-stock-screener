# AI 使用与验证记录

> 本题为笔试实现，本文件如实记录 AI 工具的使用范围、参与环节，以及候选人（开发者）对 AI 输出的修正过程。**核心代码逻辑（筛选引擎、数据口径、合规边界）由候选人逐行核验，AI 生成内容未直接作为最终结论。**

## 一、使用的 AI 工具

| 工具 | 用途 |
|---|---|
| 豆包（本 Agent，AI Coding） | 产品架构设计、后端/前端代码生成、测试脚本编写、文档起草 |
| Node.js（本地） | 仅用于前端 JS 语法校验（`node --check`），非 AI |
| Python（本地） | 运行测试、启动服务，非 AI |

## 二、AI 参与的环节

1. **架构设计**：提出"AI 理解层 / 确定性筛选引擎 / 数据层"三层职责分离，并据此组织代码（对应题目考点）
2. **指标与条件模型**：设计 21 个指标的口径（单位/方向/类别）、7 种操作符、12 组预设意图的默认口径
3. **代码生成**：后端（Flask API、解析器、引擎、数据层、回测、存储）与前端（单页应用）主体代码
4. **测试脚本**：冒烟测试（41 项）与端到端 API 测试（23 项）
5. **文档**：README、测试说明、本记录

## 三、候选人修正的 AI 错误（真实记录）

| # | 问题 | 发现方式 | 修正 |
|---|---|---|---|
| 1 | `INDUSTRIES` 从 `schema` 导入，但常量定义在 `demo_data`，导致服务启动即崩溃 | 启动服务报 `ImportError` | 改为从 `demo_data` 导入（app.py、parser.py） |
| 2 | `_extract_compare()` 定义带多余参数，调用处缺参抛 `TypeError` | 冒烟测试崩溃 | 删除多余参数 |
| 3 | 规则解析"排除行业"匹配到第一个行业即 `break`，`"剔除银行和地产"`只解析出银行 | 冒烟测试失败 | 改为收集片段内全部命中行业，并跨片段合并为单个条件 |
| 4 | 条件满足度计算中 `cond.get("type") != "metric"` 对普通条件（无 `type` 键）恒为真，导致所有条件被跳过、满足度恒为 0 | 浏览器验证发现"满足度 0%" | 改为 `cond.get("type", "metric") != "metric"` |
| 5 | 前端弹窗文案中的 ASCII 引号截断 JS 字符串，页面脚本报语法错误 | `node --check` 校验 | 改用中文引号「」 |
| 6 | 端到端测试脚本把 HTTP 400（预期业务错误）当异常抛出导致中断 | 首次 e2e 运行崩溃 | 测试客户端兼容读取错误响应体 |
| 7 | 演示数据中"盈利增速"等字段的口径不一致（部分股票缺字段会静默跳过） | 代码审查 | 数据层强制字段级 `None` 显式暴露，引擎单独归类"数据缺失" |
