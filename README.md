# 选股意图解释器 · NL Stock Screener

**题目 02｜自然语言智能选股与策略解释器** 的可运行实现。

把"经营改善、估值合理、走势相对稳定"这类模糊选股意图，转成**可检查、可修改、可执行**的结构化数据条件，返回有真实行情支撑的候选股票，并逐条解释**每只股票为何入选、为何被排除、条件变化会带来什么影响**。

---

## 一、产品定位

| 项 | 说明 |
|---|---|
| 目标用户 | A 股个人投资者 / 研究型用户：有模糊选股想法，但不会写筛选公式、看不懂黑盒选股结果 |
| 核心价值 | ① 自然语言 → 结构化条件的透明转化（口径可检查、可修改）② 入选/排除的逐条件解释（含差距与数据缺失）③ 条件敏感性分析（改一个条件看谁进谁出）④ 结果可比较、可保存、可回测 |
| 合规底线 | 不输出确定性涨跌预测、收益承诺或直接买卖建议；事实、推断、不确定信息区分展示；核心结论可回溯到字段与来源 |

## 二、三层职责边界（本题核心考点）

```
┌─────────────────────────────────────────────────────────────┐
│ 用户意图：经营改善、估值合理、走势相对稳定                       │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ AI 理解层（parser.py / llm_client.py）                        │
│  只做"理解"：自然语言 → 结构化条件 + 意图标签 + 口径说明          │
│  LLM（可选，配置 Key 后启用）＋ 规则解析（零依赖回退）双通道       │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 确定性筛选引擎（engine.py）                                    │
│  只做"判断"：逐条件求值（通过/未通过/数据缺失）、差距计算、         │
│  冲突识别、敏感性、比较。全程无 LLM，结果可复现可审计。            │
└──────────────────────────────┬──────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 数据层（data_provider.py / demo_data.py / fuyao_client 预留）  │
│  只做"取数"：字段级标注来源、时点、口径；缺失显式暴露，不静默补全   │
└─────────────────────────────────────────────────────────────┘
```

- **AI 不筛选**：LLM 只负责把话翻译成 JSON 条件，不接触数据、不下结论。
- **引擎不猜测**：筛选是确定性的，同样的条件 + 同样的数据永远得到同样的结果。
- **数据可追溯**：每个字段标注来源（演示/实时行情/扶摇），每条解释回到具体数值与阈值。

## 三、功能清单

1. **意图解析**：LLM（OpenAI 兼容，默认火山方舟）或规则解析，输出结构化条件 + 意图标签 + 默认口径说明 + 未覆盖维度提示
2. **条件编辑器**：逐条可改（指标/比较符/阈值）、可删、可加；支持剔除 ST、排除行业
3. **冲突识别**：同指标互斥区间（error）、语义冲突如"大盘蓝筹+小盘股"（error）、"高成长+低波动"（warning）
4. **确定性筛选 + 解释**：入选（按条件满足度排序）、被排除（决定性原因 + 差距）、接近入选（near-miss）、数据缺失单独归类
5. **条件敏感性（What-if）**：修改任一条件阈值 → 新增/掉出清单 + 数量守恒核对
6. **横向比较**：勾选多只股票并排对比关键指标与逐条件通过情况
7. **回测（演示）**：等权持有 N 日 vs 模拟沪深300基准，绘制净值曲线（显式标注模拟）
8. **策略保存**：本地 JSON 保存/加载/删除
9. **实时行情增强**：腾讯公开行情刷新 PE/PB/市值/换手率（实时来源字段级标注），财务指标保持演示口径
10. **数据缺失治理**：缺失值不判定为"未通过"，单独归类并解释，绝不静默补 0

## 四、快速开始

```bash
# 1. 安装依赖（仅 Flask）
pip install -r requirements.txt

# 2. 启动
python app.py
# 或 Windows 双击 run.bat；macOS/Linux 运行 ./run.sh

# 3. 打开
#   http://127.0.0.1:8000
```

**无需任何 API Key 即可跑通完整主链路**（默认规则解析 + 演示数据）。

## 五、环境变量（可选增强）

| 变量 | 作用 | 默认 |
|---|---|---|
| `LLM_API_KEY` | 启用 LLM 解析（火山方舟等 OpenAI 兼容服务） | 未设置 → 规则解析 |
| `LLM_MODEL` | 模型名（如 doubao-seed 系列） | 必填才启用 |
| `LLM_BASE_URL` | API 地址 | `https://ark.cn-beijing.volces.com/api/v3` |
| `FUYAO_API_KEY` | 启用扶摇真实财务数据 | 未设置 → 演示数据 |
| `FUYAO_BASE_URL` | 扶摇服务地址 | `https://fuyao.aicubes.cn` |
| `PORT` | 服务端口 | `8000` |

Windows 设置示例（run.bat 顶部）：
```bat
set LLM_API_KEY=你的key
set LLM_MODEL=你的模型名
set FUYAO_API_KEY=你的key
```

## 六、数据来源与口径

| 来源 | 用途 | 状态 |
|---|---|---|
| 演示数据集（`demo_data.py`） | 76 只 A 股、覆盖 20+ 板块的财务/行情指标，**构造数据，非真实** | 默认启用，全局横幅标注 |
| 腾讯公开行情 `qt.gtimg.cn` | PE(TTM)/PB/总市值/换手率/涨跌幅（实时） | 「刷新实时行情」按钮，字段级标注"腾讯行情·实时" |
| 扶摇金融数据 API | 真实财务指标（营收/净利/ROE/毛利率等） | 适配器骨架已就绪，按下方「数据接入」补齐字段映射 |
| iFinD MCP | 新闻/宏观/跨市场（题目可用源） | 当前版本未接入，属已知边界 |

**缺失处理**：任何字段缺失（`None`）→ 该股归类"数据缺失"，原因中写明缺失字段；接口失败 → 显式报错并保持可用数据，不静默生成"正常"结论。

### 数据接入（接入扶摇后）
1. 在扶摇官网签发 API Key，设置 `FUYAO_API_KEY`
2. 在 `data_provider.py::FuyaoProvider.get_universe()` 按扶摇文档（`https://fuyao.aicubes.cn/docs/`，REST `/api/A股/...` + 统一 ApiResponse 信封）补齐三段映射：
   - 标的列表 → 代码/名称/板块/行业/ST
   - 行情快照 → pe_ttm/pb/mkt_cap/turnover_20d/amount_20d/mom_20d/mom_60d/vol_20d/drawdown_60d
   - 财务报表 → revenue_yoy/profit_yoy/profit_cagr3/roe/gross_margin/net_margin/debt_ratio/ocf_to_profit/dividend_yield
3. 返回结构与 `demo_data.UNIVERSE` 一致（`STOCK_KEYS`），缺失置 `None` 即可

## 七、API 一览（统一响应信封 `{code, message, data}`）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/meta` | GET | 指标/操作符/预设意图/行业/示例句/数据状态 |
| `/api/parse` | POST | `{text}` → 结构化条件 + 意图标签 + 口径说明 + 冲突 |
| `/api/screen` | POST | `{conditions, limit}` → 入选/排除/接近入选 + 逐条件解释 |
| `/api/whatif` | POST | `{conditions, metric, value}` → 新增/掉出 |
| `/api/compare` | POST | `{codes, conditions?}` → 横向对比表 |
| `/api/backtest` | POST | `{codes, days}` → 演示回测（模拟序列，显式标注） |
| `/api/saves` | GET/POST | 策略列表 / 保存 |
| `/api/saves/<id>` | DELETE | 删除策略 |
| `/api/quotes/refresh` | POST | 刷新实时行情（腾讯公开源） |
| `/api/health` | GET | 健康检查 |

## 十、已知边界与未做事项

- **数据**：默认演示数据为构造口径；扶摇适配器为骨架，需按上文映射接入；iFinD 未接入
- **回测**：仅演示流程（模拟序列），未接入真实历史 K 线；不做调参/因子归因
- **监控任务**：保存策略可复用为关注列表，定时监控/推送未实现（可在 `/api/saves` 之上扩展）
- **池子**：演示池 76 只；接入扶摇后可扩展为全 A 股，分位条件随之按全市场口径重算
- **LLM 依赖**：LLM 解析质量受模型与 Key 配置影响；未配置时规则解析覆盖常见句式（见 `parser.py::_PRESET_KEYWORDS`）
- **性能**：单进程内存态，适合笔试演示与中小规模使用
